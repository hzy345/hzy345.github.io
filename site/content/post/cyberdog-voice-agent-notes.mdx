项目的目标很直接：人说一句自然语言指令，机器狗不仅能回答，还能理解其中的动作意图并执行对应动作。

![CyberDog 在武汉大学创新发明与技术实践协会线下展示现场](/projects/cyberdog-club-demo.webp)

## 系统目标

普通遥控方式要求用户记住按键与动作的映射。语音交互希望把这层操作转换成更自然的表达，例如“跟我打个招呼”或“做一个庆祝动作”。

代码中的链路同时处理两种输出：

- 文字与语音：大语言模型生成回答，再由 TTS 合成为声音；
- 机器人动作：从模型输出中解析动作意图，映射到机器狗内部已经提供的动作序列。

## 交互链路

当前可以把系统抽象成下面几个步骤：

1. ROS2 节点订阅 `asr_text`，接收机器狗的语音识别文本；
2. 程序把文本、当前姿态和情绪组合成对话输入；
3. 模型按 `response / emotion / action` 结构返回回复；
4. 程序截取并解析 JSON，校验动作编号和情绪白名单；
5. 回复经 TTS 合成为 OGG 音频，并写入机器狗的自定义语音目录；
6. ROS2 服务分别触发动作、语音、音量与 LED 灯效。

这里最值得展开的并不是“接入了大模型”，而是如何让不确定的语言输出安全地进入确定的机器人控制接口。

## 工程上需要回答的问题

### 动作如何约束

模型不应该直接生成任意底层控制指令。更可靠的做法是维护一个动作白名单，由程序把有限的动作标签映射到机器狗内部序列。

当前动作以整数 ID 传递，代码中已经包含站立、坐下、趴下、作揖、转圈、走正方形、翻滚和扭屁股等映射。模型返回非 JSON、缺少字段或情绪不在白名单时，程序最多重试三次，并使用默认回复兜底。

### 语音与动作如何同步

如果语音先结束很久动作才开始，交互会显得迟钝；如果两者完全同时触发，也可能出现动作噪声盖过语音的问题。

语音板状态回调区分“开始识别、识别完成、开始播放、播放完成”，并据此切换倾听、思考和情绪灯效。程序还会在识别时暂时静音，以减少机器狗自身声音对 ASR 的干扰。真实平均延迟和现场体验仍需通过实机记录补齐。

### 失败情况

当前源码已经处理了部分模型格式错误和 TTS 请求异常，但网络超时、连续指令冲突、动作中断恢复与服务不可用仍缺少系统化测试记录。这些会是后续复盘中最值得补充的失败案例。
